# 需求验收与证据

验收依据是用户保存的工具介绍、常见问题、项目介绍三个网页。工具介绍说明LegalKit可用于模拟评测，不含官方测试集；常见问题要求按赛道格式自查，不提供额外评分口径。具体输出和接口以智能合同审查项目介绍为准。

| 要求 | 实现 | 验证 |
|---|---|---|
| 完整合同读取、真实PID、解码后原文 | `schema.py` | 字符实体、非连续PID、重复PID和非法区间测试 |
| 三类问题、全部跨段证据、多类同段 | `pipeline.py`、`prompts.py`、`rules.py` | 公开示例、变化金额和公司名称、三类模拟模型全流程 |
| 修订一次回填、只输出修改段 | `to_submission`、`render` | 同段多类型及未修改证据段测试 |
| 原文逐字一致、无多余字段、禁止段落标签 | `validate_submission` | 原文、类型并集、重复段、空文本和p标签变体回归 |
| 双JSONL的zip根目录格式 | `package` | 生成zip并读取文件列表 |
| 本地评测与可查看的效果 | `view_sample_effect.py`、`evaluation.py` | HTML生成、转义、无gold不评分、命中/漏检展示 |
| LegalKit模拟评测 | `legalkit_adapter.py`、`legalkit_cli.py` | 上游Task/BaseEvaluator/StorageManager真实接口及JSONL往返 |
| 一合同一请求、无错误空数组、失败可重试 | `server.py` | 本机HTTP鉴权、400/503、重复请求和空结果测试 |
| 其他电脑可复现 | 子模块、`scripts/run_demo.py`、pyproject、CI | 干净目录安装及完整演示；CI在推送后另行运行 |

“目标满足”的验证范围是可运行的审查/提交/模拟评测工具链及公开示例上的已知问题。**没有获得官方15份合同、可信官方gold和真实模型接口，不能确认真实赛题总分或晋级能力。**

当前规则对少量完整公司名称冲突、无额外税费条件的显式乘法/分期链、固定交货句式的期限缺失有效；存在变更、优先、简称等信号时保守跳过相应规则。它不是通用合同理解模型。主方案仍是分类全文检测、联合修订与复核的大模型推理，需由使用者配置模型。

官方修改分需要ChERRANT、完整多参考方案、合理性复核以及特定编辑距离口径，现有材料不足以复现。项目只报告本地定位L和修订逐字诊断，不冒充R或S。公开示例参考标注由项目自行补齐，参与过开发；不得将其成绩当作官方测试成绩。

封测正式验收还需公网部署、符合公告的超时/并发、持续在线以及真实模型重复请求确定性测试；当前仅本机接口功能已验证，不保存封测合同。项目不会自动完成报名、赛事平台提交或邮件报告。
